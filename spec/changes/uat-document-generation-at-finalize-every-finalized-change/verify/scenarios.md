## Gaps

1. **Error JSON shapes (PARTIAL)** — Only the `incomplete_artifacts` error payload has an exact-shape test asserting no `uatPath`/`uatWarning` key. `conflict`, `gates_failed`, `finalize_locked`, and `finalize_error` JSON shapes are verified by code inspection only (src/cli/commands/finalize.ts: the uatPath/uatWarning fields are emitted exclusively in the success branch at lines 140-148). Risk is low — the field addition is structurally confined to the success payload — but the spec scenario enumerates all five shapes and four lack direct test assertions.
2. **Dist template delivery (PARTIAL)** — No test asserts `dist/templates/artifacts/uat.md` exists and matches source. Verified manually this run: byte-identical (`cmp`), and the `copy-templates` script is unchanged. A regression here would only surface at build/packaging time.
3. **Nuance, not a gap in behavior** — The machine-verified annotation consumes gate evidence as the in-memory `GateResult[]` passed by the finalizer (the same record later written to `gates.yaml` at Step 6b), rather than re-reading `gates.yaml` from disk. This is the only possible ordering (gates.yaml for the current run is written after UAT generation), and tests/uat-generator.test.ts:318 pins the behavior explicitly (`no gates.yaml on disk`). Cross-referencing remains best-effort and absence never errors, per spec.
