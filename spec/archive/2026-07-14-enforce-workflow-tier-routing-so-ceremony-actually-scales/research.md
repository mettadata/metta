# Research: enforce-workflow-tier-routing-so-ceremony-actually-scales

## Decision: Minimal in-place default flip + co-located escalation write + new git-log ceremony helper + unnumbered routing pre-step section

### Approaches Considered

1. **Conditional `defaultYes` flip on the existing `askYesNo` call** (selected) — `complete.ts:246` currently passes `{ defaultYes: false, jsonMode: json }` into the downscale prompt. `askYesNo` (`src/cli/helpers.ts:282-297`) already resolves non-TTY/`--json` calls to `defaultYes` (line 287-289) and auto-derives the `[Y/n]`/`[y/N]` suffix from `defaultYes` (lines 293-296). Replacing the literal `false` with `currentMetadata.workflow_locked !== true` satisfies both the interactive-default-display requirement and the non-interactive-resolution requirement with a single-line change, since `artifactId === 'intent'` (outer `if` at line 194) and `recRank < chosenRank` (line 225) already scope the block to "artifact is intent, scored below current."
2. **Add a separate non-TTY branch before calling `askYesNo`** — rejected: duplicates logic `askYesNo` already implements, and risks the two paths drifting.
3. **Flip `askYesNo`'s own default parameter globally** — rejected: `askYesNo` is reused for the upscale prompt (line 317-323) and the post-implementation upscale prompt (line 415-420), both of which must keep `defaultYes: false` unconditionally per spec's "Everything else about the scorer is unchanged."

### Rationale

Approach 1 is the smallest possible diff that satisfies `AutoDownscalePromptAtIntent`: one line at `complete.ts:246` changes from `defaultYes: false` to `defaultYes: currentMetadata.workflow_locked !== true`. No changes needed in `helpers.ts` — its existing non-TTY/`--json` short-circuit and suffix logic already do the right thing once `defaultYes` is correct.

**Escalation write point.** `ArtifactStore.updateChange` (`src/artifacts/artifact-store.ts:80-88`) merges a `Partial<ChangeMetadata>` and Zod-validates the merged object against `ChangeMetadataSchema` on every write via `state.write`. This is the same call already used at `complete.ts:277-280` and `342-345` to persist `workflow`/`artifacts`. Recommend writing `escalation` through the same `updateChange` call inside the `complete.ts` intent-scoring block (not a new `ArtifactStore` method) — it stays co-located with the decision that produces it, is automatically Zod-validated, and matches the existing pattern where `complete.ts` composes metadata patches directly rather than the store owning decision logic.

**Justification source in non-interactive mode.** Rejected adding a `--justify` flag: `complete.ts`'s scoring block is deliberately advisory-only and wrapped in a swallow-all `try/catch` (line 361) so it never blocks completion; a required flag would force every non-interactive/orchestrator caller to pass it or fail silently into an unjustified escalation. Recommend a default canned string keyed by cause — e.g. `"kept <tier>: workflow_locked"` when `workflow_locked === true` suppressed the Yes default, or `"kept <tier>: declined downscale (non-interactive)"` when an unlocked prompt resolved No via non-TTY/`--json`/auto-off. `EscalationRecording`'s scenarios only require a non-empty string, not a user-authored one; a flag can be added later if operators want custom text.

**Ceremony metrics.** `progress.ts` today has no repo-wide git log call; its only git access is `getGitLogTimings` (`src/util/git-log-timings.ts:18-34`), which runs `git log --format=%aI -- <single-file>` per artifact as a legacy-timing fallback — it is not usable for a repo-wide commit classification. Recommend a sibling helper (same execFile/promisify/never-throw pattern) that runs `git log --format=%s` once across the whole repo and classifies each subject line's `^(\w+)(\(.+\))?:` prefix into chore/docs vs total. This is more reliable than parsing archive metadata, since git history includes non-metta commits and archive directories don't store individual commit messages.

For artifacts-per-small-change: contrary to the research prompt's premise, archived `.metta.yaml` files *do* retain the final `workflow` field — `ArtifactStore.archive` (`artifact-store.ts:108-117`) simply `rename`s the whole change directory into `spec/archive/`, it does not strip `.metta.yaml`. Confirmed by sampling: `spec/archive/2026-06-23-fix-stale-documentation-.../​.metta.yaml` has `workflow: quick`; `spec/archive/2026-04-06-metta-docs-generate-.../.metta.yaml` has `workflow: standard`. No fallback is needed — filter `spec/archive/*/.metta.yaml` for `workflow === 'quick' || workflow === 'trivial'`, average `Object.keys(artifacts).length`, and render the spec's required no-data indicator only when the filtered set is empty.

**Skill routing pre-step.** `spec/specs/skill-template-consistency-enforcement/spec.md` turned out to govern the PreToolUse Bash guard (blocking direct `metta <cmd>` calls without `METTA_SKILL=1`), not SKILL.md structural/section conventions — a mismatch with the research prompt's assumption. The only enforced constraints on `metta-propose/SKILL.md` are byte-identical-copy tests (`tests/grounding.test.ts:34-38`, `tests/skill-discovery-loop.test.ts:71`) between `src/templates/skills/metta-propose/SKILL.md` and `.claude/skills/metta-propose/SKILL.md`, plus a substring check for "Concrete-tech grounding" (`grounding.test.ts:42`). Given `SkillRoutingPreStep` requires the pre-step run "before its existing Step 1," and Steps 1-9 are cross-referenced by number elsewhere in the file (e.g. line 92, 97 reference "Step 4"), recommend inserting an unnumbered `## Routing pre-step (run before Step 1)` section directly above the `## Steps` heading (line 14) rather than renumbering — avoids churn to ~10 existing step-number cross-references, then update the deployed copy identically to keep the byte-identical tests green.
