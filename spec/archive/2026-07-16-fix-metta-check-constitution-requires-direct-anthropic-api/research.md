# Research: fix-metta-check-constitution-requires-direct-anthropic-api

## Decision: Split `checkConstitution` into `buildCheckContract()` (survives) + `recordVerdict()` (new), drop the `provider` field entirely, delete `src/providers/`, add `--record <file>` to the existing command, and rewrite the skill to spawn the subagent between two CLI calls.

### Approaches Considered

**1. Split `checker.ts` into two exported functions vs. keep one function with a mode flag.**
`checkConstitution` (`src/constitution/checker.ts:83-135`) currently does three things in sequence: (a) parse constitution + read spec (`parseConstitution`, `readFile` — lines 93-94), (b) call `opts.provider.generateObject` (line 97), (c) post-process into `CheckResult` (`parseComplexityTracking`, blocking classification — lines 103-134). Only (b) requires deletion. Two options: keep a single function with a `mode: 'emit' | 'record'` branch, or split into `buildCheckContract(projectRoot, changeName)` returning `{articles, specPath, specContent}` and `recordVerdict(verdict, projectRoot, changeName)` returning `CheckResult` (reusing lines 103-134 verbatim). **Chosen: split into two named functions.** A mode flag would keep dead branches coupled in one function signature and force `CheckerOptions` to carry fields relevant to only one path (contradicts the story's explicit requirement that `CheckerOptions` drop `provider` cleanly — US-4 AC3). Two functions also map 1:1 onto the two CLI invocations and are independently testable, matching the existing near-1:1 test-to-source convention.

**2. `--record` flag on the existing `check-constitution` command vs. a new subcommand (`check-constitution-record`).**
No command in `src/cli/commands/` currently defines a `--record <file>`-style input-file flag; the closest analog is `complete.ts` reading an artifact file at a conventional path (`src/cli/commands/complete.ts:183`), not a `--flag`. Commander in this repo consistently models two-phase or conditional behavior via an optional flag on one command rather than a second command (e.g. `--dry-run` on `finalize.ts:17`, `ship.ts:9`; `--fix` on `doctor.ts:11`). **Chosen: `--record <verdict-file>` option on the existing `check-constitution` command**, branching in the `.action()` handler: no `--record` → emit contract; `--record <path>` present → read+parse+validate+persist. This preserves the single command surface the skill and stories already reference (`metta check-constitution --change <name> --json` / `--record <verdict-file>`) and avoids adding an undocumented second command family, consistent with Out of Scope item 6 ("no new commands beyond what's needed").

**3. Contract emission shape: reuse `instructions.ts`'s envelope vs. a bespoke object.**
`instructions.ts` (`src/cli/commands/instructions.ts:133-142`) emits `outputJson({...output, metta_agent: mettaAgent})` — a flat object with `agent`, `template`, `context`, `budget`, `output_path` fields, always JSON-shaped regardless of `--json`, with human mode printing a rendered banner. `check-constitution`'s existing non-JSON branch (`check-constitution.ts:122-137`) is closer to a plain human report than a template-emission format. **Chosen: mirror `instructions.ts`'s pattern of always producing a structured object under `--json`** (constitution articles, spec path/content, expected shape) but keep human mode as a readable summary (article count, spec path) rather than dumping full spec content to the terminal — full content only needs to reach the subagent, which the skill does via the `--json` output. This keeps `outputJson`/`getErrorMessage`/exit-code conventions from `helpers.ts` unchanged.

### Rationale

`checker.ts`'s prompt-building functions (`formatArticles` lines 52-62, `buildUserPrompt` lines 64-81, `SYSTEM_PROMPT` lines 30-50) and the constitution-parsing call (`parseConstitution`, imported from `./constitution-parser.js` line 5) are pure and provider-agnostic — they survive as the contract emitter, repurposed: `formatArticles`/`buildUserPrompt` become the JSON contract fields instead of an LLM prompt string (or are dropped in favor of emitting `articles`/`specPath`/`specContent` as structured JSON directly, since a subagent invoked via skill doesn't need a flattened prompt string — the skill/agent already parses `<CONSTITUTION>`/`<SPEC>` tags itself per `.claude/agents/metta-constitution-checker.md:12`). `isBlockingViolation` (`checker.ts:141-143`) and the justification-lookup block (`checker.ts:103-134`, using `parseComplexityTracking` from `./complexity-tracking.js`) survive unchanged into `recordVerdict`. Only the `AIProvider` import (line 4), the `provider` field on `CheckerOptions` (line 25), and the `generateObject` call block (lines 96-101) are deleted. `renderViolationsMd`/`renderViolationLine`/`getSpecVersion` live in `check-constitution.ts:18-67`, not `checker.ts` — these are CLI-layer rendering and are untouched, called from the new `--record` branch instead of the current single action body.

`ViolationListSchema` (`src/schemas/violation.ts:14-17`, `ViolationSchema` at lines 6-11: `article`, `severity` (`critical|major|minor`), `evidence`, `suggestion`) already exists and already matches the `metta-constitution-checker` agent's documented output contract (`.claude/agents/metta-constitution-checker.md:18-26` lists exactly these four fields) — **no new schema is needed**; `--record` validates input with `ViolationListSchema.parse()`/`.safeParse()` directly, satisfying US-2/spec's "Verdict Schema Validation" requirement with existing code.

Provider deletion inventory is small and closed: `src/providers/provider.ts` (`AIProvider`, `ProviderError`, `ProviderRegistry`) and `src/providers/anthropic-provider.ts` (`AnthropicProvider`, imports `@anthropic-ai/sdk`), barrel-exported at `src/index.ts:4-5`, imported only by `src/constitution/checker.ts:4` and `src/cli/commands/check-constitution.ts:13,96`, plus tests `tests/provider.test.ts` (full file, dedicated to `ProviderRegistry`/`ProviderError`) and `tests/constitution-checker.test.ts` (imports `AIProvider`/`ProviderError` at lines 10-11, builds a `MockProvider` fixture at lines 36-43 to inject via `CheckerOptions.provider` — this file needs rewriting to construct `CheckResult` via the two new functions instead of a mock provider). `grep -rn "anthropic" -i src/ tests/` turns up no other production consumer: `config-loader.ts:84` is just a comment example (`METTA_PROVIDERS__ANTHROPIC__...`), and `tests/config-loader.test.ts:132-138` tests generic config-loading with `anthropic` as an arbitrary string value, unrelated to the SDK — neither needs to change. `doctor.ts` does not reference API keys or providers at all (no match). `package.json:32` is the sole `@anthropic-ai/sdk` dependency line; no devDependency or test mocks the SDK module itself (only `tests/cli-complete.test.ts:19` mocks `node:readline`, unrelated).

**Surprise:** `tests/cli-issue-backlog.test.ts:288-323` contains a `describe('metta check-constitution', ...)` block with two tests that set/unset `ANTHROPIC_API_KEY` and assert exit 4 on both missing-change and no-API-key cases — this file is not in the stories/spec Impact list but must be updated (the "no API key" test's premise disappears; the missing-change test's assertion of `check_constitution_error` should still hold since contract emission still needs a valid change).

The skill (`.claude/skills/metta-check-constitution/SKILL.md`, byte-identical to `src/templates/skills/metta-check-constitution/SKILL.md`, confirmed via diff) currently does none of the subagent-spawning work described in the proposal — it is a thin wrapper that calls `metta check-constitution --change <slug> --json` once and reports the result (steps 1-5, lines 11-31). It must be rewritten to: call the emit-contract step, spawn `metta-constitution-checker` (already `tools: [Read]`-restricted per its frontmatter, `.claude/agents/metta-constitution-checker.md:4`) with the emitted articles/spec content, then call `--record` with the captured `{"violations": [...]}` output. The agent's input/output contract already matches `ViolationListSchema` exactly and needs no changes (confirmed per Out of Scope item 4).

`spec/project.md:16` — the exact line to remove is `  - Anthropic SDK — AI provider integration` under the `## Stack` → `**Frameworks & libraries:**` list (lines 11-16); replace with a stated instruction-mode-only principle per US-5.
