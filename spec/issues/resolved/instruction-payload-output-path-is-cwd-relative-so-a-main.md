# Instruction payload output_path is cwd-relative, so a main-root session driving a worktree-hosted change still writes artifacts into the main checkout. Found by correctness review during fix-root-invoked-instructions-context-complete-emit-main (which re-rooted changePath/specDir/git-cwd but scoped output_path out). Evidence: src/context/instruction-generator.ts:133 emits output_path as the relative string 'spec/changes/<name>/<file>'; skills (.claude/skills/metta-propose/SKILL.md:303/330/338, metta-plan/SKILL.md:43/50) instruct subagents to 'Write the file {output_path}' and 'git add {output_path}' from the session cwd, so for a worktree-hosted change invoked from the main root the artifact is written and committed to <main-root>/spec/changes/<name>/ — the change dir the worktree never sees. Mitigation shipped in that change: worktree-aware 'metta complete' now fails loudly (artifact not found) instead of validating the wrong tree, so the failure is no longer silent. Candidate fix: emit output_path (and any other payload path fields consumed for writes) as absolute change-rooted paths via resolveChangeRoot, or add an explicit change_root field to the instruction contract and update skills to join against it. Related follow-ups from the same review, fold in or split as appropriate: (a) stored absolute worktree path in .metta.yaml is preferred over the freshly discovered host (artifact-store.ts:145-147) and goes stale on repo move/cross-machine resume — prefer discovered host; (b) complete.ts/instructions.ts never assertSafeSlug the --change argument before join('spec','changes',changeName), unlike context.ts:50 — a '../..' change name could traverse.
