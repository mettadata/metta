## Symptom
`metta check-constitution --change enforce-workflow-tier-routing-so-ceremony-actually-scales --json` exits 4 with "Could not resolve authentication method. Expected either apiKey or authToken" whenever `ANTHROPIC_API_KEY` is unset — which is the normal state for this project, whose design principle (user directive 2026-07-14) is that everything AI-driven runs from within the Claude Code session via skills and subagents, never via direct API calls. Hit live 2026-07-13; the session worked around it by spawning the metta-constitution-checker subagent directly (which needs only Read access), proving the subagent path is sufficient.

## Root Cause Analysis
`check-constitution` is the only lifecycle step still built on the direct-API execution model. `registerCheckConstitutionCommand` unconditionally constructs `new AnthropicProvider({ apiKeyEnv: 'ANTHROPIC_API_KEY' })` and passes it to `checkConstitution`, which calls `provider.generateObject(...)` — the single `generateObject` call site in the codebase (grep confirms no consumer of the provider outside `src/providers/` other than this pair). `AnthropicProvider`'s constructor builds an Anthropic SDK client from whatever key it resolves (possibly `undefined`); with no key, the SDK throws the "Could not resolve authentication method" error when `messages.create` runs, and the command's catch-all maps every failure to exit 4. Every other AI-driven step uses instruction mode (the CLI emits a contract and the matching skill spawns a metta-* subagent); this command predates that pattern and never migrated, so it hard-fails in keyless environments and keeps the `AIProvider` abstraction plus the `@anthropic-ai/sdk` dependency alive as its sole consumer. Git history shows the command was added in the T3 constitutional-gates work (`afe3c14d7`, `12bcc9538`) atop the Phase 1 provider foundation (`5777126cb`) and has not been revisited since.

### Evidence
- `src/cli/commands/check-constitution.ts:96` — the command unconditionally instantiates `AnthropicProvider({ apiKeyEnv: 'ANTHROPIC_API_KEY' })`, making an API key a hard requirement for the whole check; the surrounding catch block (line 149) converts the resulting SDK auth error into exit 4.
- `src/constitution/checker.ts:97` — `checkConstitution` calls `opts.provider.generateObject(...)`, the codebase's only `generateObject` consumer, so the failure site sits directly on the API path with no instruction-mode alternative.
- `src/providers/anthropic-provider.ts:19-20` — the constructor resolves the key from env and builds `new Anthropic({ apiKey })`; with no key the SDK cannot resolve an authentication method and the request throws, producing the observed message.

## Candidate Solutions
1. **Rework to instruction mode (suggested direction)** — `metta check-constitution` emits the check contract (constitution articles parsed from `spec/project.md`, the spec path, and the expected violations JSON shape from `ViolationListSchema`) instead of calling the API; the metta-check-constitution skill spawns the metta-constitution-checker agent (Read-only) to produce the verdict, and the CLI (or a follow-up CLI call reading the verdict on stdin) validates the violations JSON against the schema and persists `violations.md` using the existing justified/blocking annotation logic in `checker.ts`. Tradeoff: introduces a two-phase CLI protocol (emit contract, then persist verdict), and the command no longer works standalone for a human in a terminal without an AI session driving it.
2. **Instruction mode plus full provider removal** — do (1) and also delete the `AIProvider` abstraction in `src/providers/`, drop the `@anthropic-ai/sdk` dependency, and update `spec/project.md`'s stack section ("Anthropic SDK — AI provider integration") to state the no-direct-API principle, per the 2026-07 framework review finding that `generateObject` at `checker.ts:97` is the abstraction's only consumer. Tradeoff: larger blast radius — provider references in specs, config, and tests must be reconciled, and any future genuinely headless use case would require rebuilding the provider layer from scratch.
3. **Keep the API path as an explicit opt-in fallback** — implement instruction mode as the default but retain `AnthropicProvider` behind an explicit flag (e.g. `--provider anthropic`) for CI or headless runs where a key is deliberately provided. Tradeoff: preserves the SDK dependency and dual code paths that the design principle wants eliminated, carrying ongoing maintenance and drift risk for a path the project does not exercise.
