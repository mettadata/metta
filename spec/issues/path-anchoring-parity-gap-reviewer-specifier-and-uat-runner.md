# Path-anchoring parity gap: reviewer, specifier, and uat-runner agent templates lack the shell-write path discipline shipped for executors/verifiers in PR #97

**Captured**: 2026-08-18
**Status**: logged
**Severity**: minor

## Symptom
The shell-write path discipline shipped in PR #97 (change `fix-guard-edit-worktree-write-friction-caused-cross-repo`, archived 2026-08-18) hardened only the executor and verifier agent templates plus 7 skills: those gained `change_root`-anchored write rules and Deviation Rule 6 (STOP on a silent-write anomaly; never fall back to a bash rewrite). The reviewer, specifier, and uat-runner agent templates — `src/templates/agents/metta-reviewer.md`, `metta-specifier.md`, `metta-uat-runner.md` and their deployed `.claude/agents/` twins — carry no equivalent discipline, so those personas can still fall back to unanchored shell writes when a `Write`/`Edit` tool call misbehaves inside a worktree-hosted change, risking the same cross-repo contamination the original fix closed for executors and verifiers.

## Root Cause Analysis
The PR #97 remediation was scoped to the personas implicated in the original incident (executor and verifier) rather than to the full set of agent templates that perform file writes. The reviewer template instructs a write to a bare cwd-relative path (`spec/changes/<change>/review.md`) with no `change_root` anchoring and no shell-write rules; the uat-runner template goes further and *sanctions* a heredoc fallback (`cat <<'EOF' > <path>`) for guard-edit refusals without distinguishing the refusal case from the silent-write-anomaly case that Rule 6 forbids bash-rewriting, and without requiring the target to be an absolute `change_root`-anchored path. The regression lint that keeps this pattern class from reappearing (`tests/skill-template-anchoring.test.ts`) only walks the two skill trees (`.claude/skills`, `src/templates/skills`), so agent templates are structurally outside its coverage — nothing mechanically flags the parity gap.

### Evidence
- `src/templates/agents/metta-executor.md:21-29` — carries the full discipline (Rule 6 STOP on silent-write, all bash writes MUST target absolute paths under `change_root`, no-`change_root`-no-bash-writes), the baseline the other personas lack; `grep -c change_root` returns 0 for the reviewer, specifier, and uat-runner templates.
- `src/templates/agents/metta-uat-runner.md:21` — sanctions a heredoc fallback on Edit refusal with no `change_root` anchoring and no silent-write/refusal distinction, the exact bash-rewrite shape Rule 6 forbids in the executor/verifier templates.
- `tests/skill-template-anchoring.test.ts:20` — `SKILL_TREES` enumerates only skill directories, so the anchoring lint never inspects `src/templates/agents/` or `.claude/agents/`, leaving agent-template regressions undetected.

## Candidate Solutions
1. **Extend the discipline to the three remaining templates and widen the lint** — Port the executor/verifier Shell-Write Path Discipline block and the Rule 6 silent-write STOP rule into `metta-reviewer.md`, `metta-specifier.md`, and `metta-uat-runner.md` (template + `.claude/agents/` twin, kept byte-identical), adapting wording per persona — notably carving out the uat-runner's sanctioned refusal-triggered heredoc fallback so it remains legal only for explicit guard refusals at a `change_root`-anchored path, mirroring the verifier's refusal-vs-silent-write distinction. Add an `AGENT_TREES` walk to `tests/skill-template-anchoring.test.ts` so agent templates are lint-covered. Tradeoff: mechanical duplication of the same prose across six files, and per-persona wording adaptation (especially uat-runner) invites subtle drift between pairs if the byte-identical check is not also enforced.
2. **Factor the discipline into a shared build-time include** — Move the shell-write discipline into one canonical snippet composed into each agent template at build time, eliminating duplication and drift by construction. Tradeoff: templates are currently copied to `dist/` verbatim per project convention; introducing template composition adds build machinery and violates the "template files are copied, never assembled" simplicity for the sake of one shared paragraph.
3. **Lint-first enforcement only** — Extend `skill-template-anchoring.test.ts` to scan agent templates with path-shape rules (unanchored `spec/changes/` writes, bare heredoc targets) and let the resulting failures drive the template edits. Tradeoff: regex path-shape rules can flag unanchored writes but cannot verify the presence or correctness of the discipline prose itself (Rule 6 semantics, refusal-vs-silent-write distinction), so the lint alone under-enforces the actual safety property.
