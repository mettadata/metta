# metta-guard-bash blocks main-session Tier-2 lifecycle commands despite a valid per-skill session credential

**Captured**: 2026-08-18
**Status**: logged
**Severity**: major

## Symptom
The zeus consumer session (2026-08-18) reports a clean repro: invoke `/metta-next` in-context (its PreToolUse mint hook writes `.metta/scratch/skill-session/metta-next.token` per the PR #67 per-slug design), then run `metta complete research --change <c>` from the main session — the guard returns "Blocked direct CLI call from AI orchestrator session" even though the metta-next scope includes `complete`/`finalize`. Net effect: the in-context lifecycle skills (metta-next/execute/verify) cannot reliably advance the state machine from the main orchestrator — only Tier-1 forked skills can complete artifacts, forcing forks for every lifecycle step. This matches the 2026-08-11 metta maintainer-session incident (`metta complete implementation` blocked repeatedly despite invoking metta-execute/metta-verify; worked around by handing the lifecycle to a ship fork) that was attributed to mint clobbering and considered fixed by PR #67's per-slug tokens.

## Root Cause Analysis
The audit log rules out the scope-list and subcommand-normalization candidates: every live main-session block on `complete`/`finalize` (full session event keys, 2026-07-17 through 2026-08-17) carries `reason:"credential-expired"` — the guard found a structurally valid per-slug token whose scope would have matched, but judged it past TTL. The residual bug is a TTL lifecycle gap between the two hook halves. The mint hook slide-refreshes its token only when it fires, and it fires only on main-session Bash calls (it is a skill-frontmatter PreToolUse Bash hook; Bash calls made inside dispatched subagents do not carry the invoking skill's frontmatter hooks). The dominant lifecycle pattern — skill warm-up mints the token, then the orchestrator hands artifact work to a metta-* subagent for well over the 5-minute TTL, then runs `metta complete` — therefore produces no re-prime during the gap. On the `metta complete` call itself both PreToolUse hooks fire on the same event, but Claude Code runs PreToolUse hooks in parallel with no ordering guarantee, so the guard's `now - mintedAt < ttlMs` check races the mint's same-call rewrite; when the guard reads first (or when the skill's frontmatter hook no longer applies to the later main-session call at all), the expired token loses and the call is blocked. The reporter's cwd-asymmetry candidate remains plausible as a secondary path for worktree-hosted changes (mint writes under the warm-up event's cwd, guard validates under the later call's cwd), but it would surface as `missing-credential`, which the recent live entries do not show.

### Evidence
- `.metta/logs/guard-bypass.log` — live blocks on `complete`/`finalize` with full session event keys (2026-07-17T01:18Z `complete implementation`, 02:29Z `complete research`, 06:02Z `finalize --change`, plus 2026-08-17 entries) all record `reason:"credential-expired"`, `tier:"session"`: the token existed and its scope matched, but was past TTL at guard time.
- `.claude/hooks/metta-session-mint.mjs:93` — the 80% sliding refresh only executes when the mint hook itself fires on a main-session Bash call; a >5-minute subagent-delegated work window contains no such call, so `mintedAt` is never re-primed before the next Tier-2 invocation (TTL_MS = 300000 at line 36).
- `.claude/hooks/metta-guard-bash.mjs:403` — the guard filters to `now - tok.mintedAt < tok.ttlMs` with no grace period and no coordination with the same-event mint hook, so an expired-but-about-to-be-reminted token fails closed depending on parallel hook scheduling.

## Candidate Solutions
1. **Deterministic same-call mint-before-validate** — Move Tier-2 minting out of the parallel-hook race: either register the mint logic inside the guard itself (guard consults a skill-active marker written at Skill invocation and re-primes the token before validating), or use a hook mechanism with guaranteed ordering so mint always completes before the guard reads. This fixes both the subagent-gap expiry and the race in one move. Tradeoff: couples the minting and validating halves the two-tier design deliberately separated, and requires a trustworthy "skill is active" marker that is not forgeable from orchestrator command text.
2. **Lifecycle-aware TTL** — Keep the split hooks but stop keying freshness to wall clock alone: raise TTL substantially (e.g. 30–60 min) or add a guard-side grace window sized to typical subagent execution, so tokens survive delegated work phases; keep the 80% slide for active sessions. Tradeoff: a longer-lived credential widens the window in which a compromised or stale session can drive Tier-2 mutations, weakening the trust model the short TTL was chosen to enforce.
3. **Guard integration repro tests for the mint/validate seam** — Add the deterministic repro the report asks for: mint via simulated skill warm-up, then immediate Tier-2 call from main-session cwd AND from a worktree cwd, plus a time-advanced case covering the post-subagent expiry gap and the same-event hook race. This pins the residual bug and prevents regression regardless of which fix lands. Tradeoff: tests alone do not restore the broken main-session lifecycle path; this must accompany solution 1 or 2, and simulating parallel PreToolUse hook scheduling in the suite adds harness complexity.
